# Testing

The suite uses FiveAM. [Runnable examples](examples.md#run-without-downloads) have an offline smoke-test system.

```sh
sbcl --non-interactive --eval '(require :asdf)' --eval '(asdf:test-system :cl-inference)'        # client
sbcl --non-interactive --eval '(require :asdf)' --eval '(asdf:test-system :cl-inference/local)'  # engine
```

`asdf:test-system` signals an error if any check fails. From a REPL, `(cl-inference/tests:run-tests)` and `(cl-inference/local/tests:run-tests)` return true when every check passes.

The [client](client.md) suite loads neither the engine nor cl-tensor and passes on SBCL, CCL and ECL. The CPU local fixture suite passes on all three, including GGUF tensor loading, tiny-model completions and the seeded sampler golden sequence. Real-model CPU acceptance is verified on SBCL.

Live Ollama tests are skipped unless `CL_INFERENCE_OLLAMA_URL` (the `/v1` route) or `CL_INFERENCE_OLLAMA_NATIVE_URL` is set; `CL_INFERENCE_OLLAMA_MODEL` picks the model.

Full-model checks compare against a dev-only reference kept in the gitignored `reference/` directory, which also holds llama.cpp's `ggml-vocab-llama-bpe` and `ggml-vocab-qwen2` fixtures for the tokenizer. `reference/chat-templates.py` needs `jinja2` and the two official templates in `reference/templates/`; it regenerates the chat template expectations.

[Half-precision measurements](half-linear-performance.md) benchmark complete `linear` calls, including conversion, result allocation and tensor metadata. Performance measurements run separately from test suites to avoid contention.

## Default tokenizer reference

The default-BPE fixtures cover 50 selected inputs and 100 seeded mixed-character inputs. Ordinary local tests compare splits, token IDs and decode round trips for missing, empty and explicit `"default"` GGUF pre-types. They run without external reference files.

Regenerate or verify expectations with the pinned llama.cpp checkout and its built `llama-tokenize` executable:[^default-reference]

```sh
python3 tools/default-tokenizer-reference.py
python3 tools/default-tokenizer-reference.py --check
```

The generator uses Python's standard library and a C++17 compiler (`CXX` overrides `c++`). It checks source revision and cleanliness, compiles the actual Unicode splitter, and compares token IDs across all three pre-types. It disables CLI escape processing to preserve literal input.

## Qwen35 reference

Qwen3.5 fixtures compare the actual llama.cpp Unicode splitter, token IDs and decoded bytes for a synthetic vocabulary and the pinned `ggml-vocab-qwen35.gguf`. The inputs cover Unicode `Mn`, `Mc` and `Me` marks, decomposed text, non-Latin scripts, supplementary characters, digits, punctuation, whitespace and special-token boundaries, plus 100 seeded mixed-character inputs (183 inputs total). Synthetic merges cross letter/mark boundaries to detect incorrect splits.

```sh
python3 tools/qwen35-reference.py
python3 tools/qwen35-reference.py --check
```

The generator requires Python’s standard library, a C++17 compiler and the pinned llama.cpp checkout with its shared library and `llama-tokenize` built. It verifies source revision, relevant source cleanliness, executable revision and vocabulary SHA256.[^qwen35-reference] Offline tests run all 183 splits and 732 synthetic cases under the four BOS/special combinations; another 732 cases use the real vocabulary. Real-vocabulary tests skip when the external vocabulary is absent; verification requires both `--check` and a local-suite run with that vocabulary present.

## Template and executor checks

The offline family suite compares prompts and errors with the vendored, hash-pinned template matrix.[^template-data] Regenerate expectations with development-only Jinja2:

```sh
uv run --with-requirements tools/chat-template-requirements.txt python tools/chat-template-reference.py
```

`tests/local/chat-families.lisp` checks detection, stream boundaries, schema validation, client round trips, BOS/stop IDs and control-token provenance. `tests/local/execution.lisp` compares serial execution with reversed partitions and a reusable three-worker pool, including cache/greedy results, bindings, errors and cancellation. [Parallel acceptance and measurements](parallel-inference.md#measurement) run separately.

Half-precision fixtures check executor-bound single-row dispatch, directly readable mapped offsets/padding, irregular-layout fallback and an executor that signals if scheduled. Serial activation thresholds and forced paths retain their existing coverage. The [half-weight profile](half-linear-performance.md#executor-measurements) records complete-call performance separately from correctness tests.

## MLX

After building cl-mlx, `asdf:test-system "cl-inference/mlx"` runs native model, client and acceptance-harness fixtures. `asdf:test-system "cl-inference/mlx/acceptance"` compares real Llama and Qwen models with a pinned Python MLX oracle. Set `CL_INFERENCE_MLX_ACCEPTANCE_STRICT=1` to require every reference input and case; absent inputs skip in ordinary runs, while hash mismatches fail. See [MLX acceptance](mlx-acceptance.md) for setup and numerical bounds.

## Acceptance

`cl-inference/local/acceptance` checks Llama 3.2 1B Instruct and Qwen3 0.6B in F16 and Q8_0 against a pinned llama.cpp reference. It compares metadata, prompt ids, layer outputs, final logits and greedy generation.

Models and oracle dumps stay in gitignored `reference/`. Missing inputs skip individual cases; skips do not establish acceptance. See [Model acceptance](acceptance.md) for downloads, commands and numerical bounds.

Q4_0, Q4_K_M and Q6_K real-model cases use a F32-dequantized reference. See [Q4/Q6 acceptance](quant-acceptance.md) for reproducible preparation and strict verification.
