# Roadmap

Expand cl-inference model coverage and inference features first. Child-library work ranks by the parent capability it enables.

**Audit: 20 October 2026 · GitHub · 175 open issues across four repositories.** GitHub is authoritative for ticket state; this document records work order and next actions.[^audit]

## Priorities

| Tier | Importance | Work |
|---|---|---|
| P0 | Critical | Correctness or blockers on the main SBCL inference path |
| P1 | High | Additional models, formats, inference features and GPU tensor expansion, plus concrete child-library prerequisites |
| P2 | Medium | Substantial measured performance, reliability, CI and ECL/CCL correctness |
| P3 | Low | Small optimizations, convenience, other Lisps, Windows/BSD and peripheral targets |

SBCL is primary; ECL and CCL are secondary. Windows/BSD stay low priority even for those Lisps. GPU tensor expansion and its upstream capability prerequisites are P1. Other generic tensor or BLAS APIs rank high only when they enable a selected inference capability. Promote performance work when a real model demonstrates a material bottleneck.

## Work order

1. **Select the next model or format.** Gemma 3 270M IT floating Safetensors and Q8_0 GGUF have CPU/MLX acceptance; SmolLM2 135M FP32 ONNX has CPU acceptance. Select the next model or format; [support](support.md) defines the verified boundary.
2. **Pair the model with usable artifacts.** Deliver its exact tokenizer pipeline, template and format-specific weights/norms. Do not treat every tokenizer variant as a prerequisite.
3. **Expand direct GPU execution.** Integrate joins and the reviewed complex storage interface, close f64 matrix/gather/fusion gaps, and add direct encoded/packed weight products. Tensor broadcast arithmetic, masks, conversion, f32 fusion, gather, reductions/normalization and f32 matrix operations exist. Native-f64 tensor storage/non-BLAS operations have PoCL acceptance; Metal rejects f64 tensors. Shared c32/c64 GPU primitives have device acceptance, while tensor integration remains separate. Tensor f16/bf16 is storage-only. Require pinned whole-model acceptance for a selected GPU route; ONNX providers and extra MLX formats remain separate paths.[^f64-update][^complex-update]
4. **Remove measured inference bottlenecks.** Reproduce mapped F32 snapshots, serial half-weight layout packing, Q8 prefill, MLX packed-tile/cache traffic and long-context attention costs. The CPU vector bulk-copy path has [Qwen inference measurements](https://github.com/communal-software/cl-tensor/blob/trunk/docs/copy-performance.md); profile remaining matrix and allocation costs. Preserve complete-call benchmarks and acceptance.
5. **Keep validation alongside each feature.** Run the existing suites first, add fixtures and a small example, and keep support/limitations docs current. Use pinned real-model acceptance for new model routes.

The pinned [TinyLlama](hf-sentencepiece.md) and [Gemma](gemma-hf.md) HF character-BPE pipelines have exact token-ID, decode and streaming coverage. Other pipelines require their own artifact selection.[^tokenizer-update]

## Keep this roadmap current

At each work session, recheck the selected ticket on GitHub. Set its row to `Active — owner`, `Blocked — prerequisite`, or `Open`; add the next concrete action. Record completion evidence before closing the ticket, then remove its row and update counts. Preserve durable validation in the relevant feature docs.

Keep one row per open issue, including umbrellas; umbrellas coordinate their children and do not add an independent delivery estimate. Recheck all four trackers after each audit batch. Reconsider tiers when a selected model establishes a new dependency or a measured bottleneck.

Use `blocked` for issues waiting on an unresolved prerequisite. Native GitHub dependencies record definite whole-issue prerequisites; the [blocked inventory](#blocked) records alternatives, partial dependencies and external gaps. Remove `blocked` when the last blocking prerequisite is satisfied, and recheck dependants when closing a prerequisite. Labels require manual maintenance.

Existing GitHub labels remain intact. Use existing `enhancement`/`arch` labels for model coverage, plus `perf` or `format` as appropriate. Roadmap tiers are planning priorities; existing `lowpri` labels do not override them.

## Limitations

This inventory tracks unresolved work; it does not certify runtime correctness or promise dates. All rows reflect open GitHub state at audit time. Model variants, new dependencies and public APIs still require design confirmation. Owner assignments are unclaimed unless a row states otherwise.

Verified Gemma, ONNX and GPU primitive coverage does not establish support for additional variants, providers or whole-model GPU inference. The template-limitation cleanup has an existing ticket. The fused triangular-solve request may be partly superseded; confirm its remaining scope before implementation. Mapped F32 cost reports need reproduction on current code. These findings are recorded in the corresponding rows below.
